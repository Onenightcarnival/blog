# 品味的定价

这周我让 agent 在两个代码库里各做一个差不多的小改动。一个是我自己按洁癖养的项目，一个是接手的老项目。前者十几次工具调用就收工了；后者 agent 把 grep、读文件、LSP 跳转翻来覆去用了近百次，上下文塞满了和任务无关的胶水代码，最后还差点改错了地方。

看了眼用量，两边差了将近十倍。同一个模型，同一个任务，价差全部来自代码本身。

那一刻我意识到：代码品味这个东西，第一次有了价格。

## 品味以前是吵不赢的

在此之前，捍卫代码质量靠什么？靠审美，靠职业操守，靠一句"以后维护起来会很痛苦"。可代码质量难以在短期内用明确的成本衡量。

维护者的沮丧、新人三个月的上手期、review 时多耗的半小时，这些代价全是隐性的，摊在工资里，财务报表上没有这一项。屎山最大的护身符就是它不要钱——至少账面上不要。所以 deadline 一来，重构永远排在最后。关于品味，人们争论了几十年，几乎没有赢过。

[上一篇](./zeroth-world-customs.md)我写过，比付不起更坏的是没有价格。代码品味恰好就是那种东西：不是没人愿意付，是它压根没被标过价。

## agent 是品味的计价器

现在代码多了一类读者，而这类读者是按量计费的。

agent 读屎山的每一步都在烧钱。命名一混乱，它就没法靠语义猜位置，只能用 grep 暴力探索，而每一步探索都在往上下文里灌垃圾。分层一不清，它就要读十个文件才能建立心智模型，其中八个是胶水。副作用一多，局部推理就失效了，它只能把半个项目装进脑子。每一次多余的跳转、每一段无关的代码，最后都变成三样东西：token 账单、延迟、出错率。

而且 agent 比人更受不了屎山。人可以靠隐性知识活下来——在项目里泡三年，哪里有坑心里有数，代码再烂也能凭记忆绕过去。agent 每个 session 都失忆重来，它是永远的新人，唯一的依靠就是代码自己把自己讲清楚。屎山对老员工来说只是不爽，对永远的新人来说是灾难。

于是技术债换了个身份。以前它是道德问题，靠愧疚感偿还，而愧疚感是可以拖欠的；现在它是财务问题，每次调用都在结算，一分都赖不掉。

## 喊 ALL IN AI 的人，还在往屎山上堆代码

讽刺的地方在这里。很多公司嘴上喊着 ALL IN AI，以为 Agent First 就是买 seat、接 API、上工作流，然后继续往原来的屎山上堆代码。

其实最实在的 Agent First 设计，恰恰是那些最老派的工程品味：明确的分层、少的胶水、克制的抽象、说人话的命名。因为优雅的代码是低熵的，可压缩的，用最少的上下文就能装进 agent 的脑子；屎山是高熵的，怎么压都压不进去。

用[《第零世界从我的账单开始》](./zeroth-world-from-my-bill.md)里的比喻说：给 agent 配最贵的模型，喂的却是屎山，等于拿着美元的汇率，换回津巴布韦币的产出。模型的钱花在了替你的烂代码考古上。

## agent 的品味是中庸的

不过 agent 认的品味，和教科书不完全是一回事。

它惩罚的其实是两个极端。一头是屎山，熵太高；另一头是过度设计，间接层太多。层层薄封装、依赖注入的魔法、反射——这些对人来说可能叫"设计模式"，对 agent 来说，每一层间接就多一次工具调用，静态分析追到一半就断了线。agent 有时反而偏好一点笨的代码：就地展开，适度重复，显式胜于巧妙。

所以它奖励的恰好是克制的那种品味：该抽象的抽象，不该抽象的忍住。这比"把代码写优雅"的要求更严格——过度设计的人以前还能拿"优雅"当挡箭牌，现在计价器对着两个方向都在跳字。

## 定价之后

我有点说不清这算品味的胜利还是降格。

吵了几十年吵不赢 deadline 的东西，靠账单一夜翻案。赢是赢了，但赢的方式，是承认审美说了不算，钱说了算。工匠精神没能挽救代码质量，计费系统做到了。

可是按上一篇的标准，这已经是好结局。品味终于从"没有价格"的世界搬进了"有价格"的世界。能被标价，在这个时代已经算温柔的待遇。

这个行业为品味争论了五十年。最后给它定价的，是一个按 token 收费的读者。
